so what are the Problems, if this is so great why does literally every kubernetes Project run into so many Problems?
well.

kubernetes does one Thing particually well:

- running Tasks, that are from the perspective of the kubernetes, stateless
what does that meaning?

It means, it doesnt have state IN THE KUBERNETES

- Needs Information -> database
- Needs congiuration -> bake it into the Images
- Needs data -> load it from S3

But if this is so easy why not just do that?, well

- some Things can't be baked into container Images because of licensing Problems, yes sounds stupid, but that happens alot acutally
- applications which write state to disk are more common than you think, volumes tmeporaray or permanent are possible in kubernetes, even as multi-node read write, but it makes Things alot more complex, the easisert way is to only have configuration, have Secrets like database Passwords and s3 keys and load everything from there
- your application requires ANY Manual Intervention or Setup, now this is a big one: Your application Needs a user to do a web based Setup? thats not going to happen, everything Needs to be declarative and loaded from configuration

So summary, your application will work great in kubernetes IF:
- your load everything concurrency safe from a database
- your datastore uses remove protocols like S3
- your application does not require any Manual intervetion or Setup

Do that and you are literally kubernetes Ready.
